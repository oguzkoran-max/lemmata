## Prompt Summary

The technical check of P053 found that Spanish text run with Italian selected passed the early language check. Looking closer, Claude found that in the app no language mismatch was reported after a successful run: the early check (P022) is shown only when the analysis fails, and the check after preprocessing (decision 58: kept lemmas over tokens below 0.10) did not fire for German, French or Spanish text run with Italian selected, because the wrong model still tags many tokens as nouns and keeps them (0.41 to 0.71). Claude proposed comparing the texts with every supported language; the first author approved the fix.

## Response Summary

- `preprocessing.py`: `detect_language_mismatch(texts, language)` takes five windows of 1,000 characters spread over each file (first 10 files; whole text if shorter), so title pages and licence boilerplate count little, and computes the share of words on spaCy's stop-word list for every supported language (`stopword_shares`, lists only, no model). If another language's share exceeds the selected one's by more than 0.10, it returns a warning naming both languages and both shares.
- `app.py`: the runner calls it before the existing check; the warning of either check is now also stored with the results and shown above the result tabs after a successful run (before, only when the analysis failed). The language selector takes its names from `config.LANGUAGE_NAMES`.
- `config.py`: `LANGUAGE_NAMES`, `LANGUAGE_CHECK_MARGIN = 0.10`, window count, size and file limit, with the measurement behind them.
- Tests: Spanish text with Italian selected is flagged; matching languages are not; English front matter before Italian text does not trigger it; text without words gives no warning.

## Decision

No methodological change. Window size, number and the 0.10 margin are technical values, not from literature, set from the measurement below.

Warning text. A first draft said that a share of the texts' words were "common function words" of each language. Claude then pointed out that this overstated what is measured: the check counts words on spaCy's stop-word lists (which also contain words such as Italian "grande") in samples, not in the whole texts. Claude proposed a corrected wording; the first author, unsure which to choose, asked for Claude's view, Claude recommended the corrected wording because it states what the program measures, and the first author approved it ("Evet", 20 Nov 2026).

## Validation

- Measurement (saved with the project records): 20 windows of 1,000 characters from each of the three Svevo novels and the three Collodi texts (120 Italian samples, plus the five-window samples) and the 12 German, French and Spanish texts of P053. With the right language selected, the best other language trailed it by at least 0.227; with a wrong language selected, another language led it by at least 0.227. No sample fell between.
- The new function on whole uploads: no warning for the six Italian texts, alone or together, nor for the German, French, Spanish and (four short texts written for this check) English sets with their own language; a warning for every one of the 16 wrong selections on these four sets.
- Markdown-heavy English prose (25 prompt logs) has an English stop-word share of only 0.11, so three wrong selections were not flagged there: the check stays silent rather than raising a false alarm when a text has few function words.
- Local app: German and Spanish texts with Italian selected show the warning above the results after the analysis; Spanish text with Spanish selected shows none.
