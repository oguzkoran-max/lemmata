## Prompt Summary
An ablation of Lemmata's preprocessing on the Decameron validation corpus (D7, in the authors' records) found that spaCy's Italian model gives some forms with clitics a lemma of several words ("farmi" -> "fare mi", "andatosene" -> "andatoe si ne"; 111 kept tokens in the corpus). Lemmata checked the stoplists against the whole lemma, so the parts reached the model: "si", "mi", "ne", "il", "li" and "ti" were in the vocabulary of the default model. Claude Code proposed to check each part against both stoplists, add a test for the case and a general test that no stopword reaches the model, and rerun the default validation arms before release. The first author's answer:

```
Evet, düzelt
```

("Yes, fix it.")

## Result
- `_process_token` checks each part of the lemma against the built-in and custom stoplists and keeps the parts that are not stopwords (`lemma_used`, also in the token trace); a token none of whose parts remain is dropped. Single-word lemmas are handled as before.
- Two tests: the parts of "fare mi", "andatoe si ne" and "sa il" that are stopwords are dropped; no stopword on either list reaches the processed texts. Both fail on the code before the fix.
- Decameron, default input (1,203 documents): 113 fewer words (47,118 to 47,005), 8,719 distinct lemmas (8,735). No word on either stoplist remains, and the new input equals the old one with only the stopword parts of multi-word lemmas removed.
