## Prompt Summary

Screenshots of v0.3.0 taken for the project website (15 November 2026, *La coscienza di Zeno*, default settings, 1440 x 900 window) showed the Topic Map cut off on the right: pyLDAvis draws at a fixed size of about 1,210 x 844 px, while the app's main column is about 980 px wide at that window size. The term bars, the relevance slider and the footnotes were only reachable by scrolling inside the frame. The first author approved fixing it as part of the technical release preparation for v0.3.0.

## Response Summary

- `visualisation.py`: new `fit_html_to_width()` wraps the pyLDAvis HTML unchanged in a container whose script measures the drawing once it appears and scales it to the frame width (CSS transform), never below 60%; below that the frame scrolls. The 60% floor is a legibility choice, not from literature.
- `app.py`: the Topic Map tab passes the map through `fit_html_to_width()`; frame height 850 px (was 800) so the unscaled map (844 px) is not cut at the bottom on wide screens.
- `tests/test_visualisation.py`: the wrapper keeps the map HTML intact and sets the floor.

## Decision

No methodological change. The map, its data and its interaction are unchanged; only its display size in the app.

## Validation

- Test page with the old and new map in frames of 1250, 940, 700 and 390 px: at 940 px the new map scales to 0.78 and every element (slider, term labels) lies inside the frame; hovering a topic still highlights its terms.
- Local app, *La coscienza di Zeno* with default settings: at a 1440 px window the map scales to 0.81 and fits; at 1920 px it is shown at full size; at 1100 px it reaches the 60% floor and the frame scrolls by 86 px.
