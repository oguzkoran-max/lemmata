## Prompt Summary

With several files, Lemmata treats each file as one document (decision 4) and caps the number of topics at half the number of documents, with a minimum of 2 (decision 164). Uploading the three Svevo novels in `examples/` therefore gave 3 documents and at most 2 topics, whatever topic count was chosen; this came up when screenshots for the project website were taken (15 November 2026). On 12 November an option to split every file had been proposed and left for the authors to decide. On 19 November the first author, after a plain-language explanation of the problem and of the two choices, decided that the option goes into v0.3.0.

## Response Summary

- `config.py`: `CHUNK_EACH_FILE_DEFAULT = True` (ticked), the authors' decision; see Decision.
- `preprocessing.py`: `process_documents(..., chunk_each_file=False)`. When set, every file longer than `chunk_size` words is split with `chunk_text()`, as a single file is (labels `name_001`, `name_002`, ...); files no longer than `chunk_size` stay whole with the file name as label, so they are processed exactly as before. The default keeps one document per file.
- `app.py`: sidebar checkbox "Split every file into parts" under the chunk size, with help text; the chunk-size help mentions it; the setting is passed to preprocessing, stored in the parameters (and so in `metrics.json`, the PDF report and the environment report), and used by `estimate_n_documents()` for the topic-count warning and time estimate.
- Tests for both settings, for short files being unchanged, for the document estimate, and for the ticked default.

## Decision

The authors decided to include the option in v0.3.0 and to have it ticked by default (19 Nov 2026; second answer: "İşaretli gelsin", "Have it ticked"). With several files longer than the chunk size, results therefore differ from earlier versions unless the box is unticked. Claude had proposed the ticked default on 12 November without a source. The wording of the label and help text was shown to the first author in Turkish translation before the commit. Splitting long texts into segments follows practice the app already cites in the chunk-size help (Schöch 2017, segments of about 1,000 words for plays; Cooper et al. 2021, 200-word documents).

## Validation

- Decameron (validation study input, 1,203 documents of Cooper et al. 2021, the D8 preprocessing path): with the option off, and with it on at a chunk size of 1,000, the processed texts and labels are identical to the saved D8 output (SHA-256 805cb6da…, as in `d8-onisleme.json`). The longest document has 200 words, so none is split at any allowed chunk size (minimum 200).
- Local app, the three Svevo novels with default settings and the option ticked (run before the default was changed to ticked): 327 documents (La coscienza di Zeno 144, Una vita 116, Senilità 67), 10 topics; the per-file chunk table lists the three files.
