# P057: Keep parsed uploads in a per-session cache

**Date:** 21 November 2026

**Category:** bug-fix

## Prompt Summary

P050 cached parsed uploads with `st.cache_data` (at most 8 entries, one hour). That cache is global: parsed texts stayed in server memory after the browser session ended and were held in one process-wide store. The app ("Texts are processed in memory during your session") and the project website ("processed in session and not stored permanently") therefore no longer described it exactly (pre-release website review, 20 November 2026). An expert agent proposed adding `scope="session"`, which keeps the statements true; Claude checked that the installed Streamlit (1.66.1) supports it ("the data is removed from the cache when the session disconnects") and presented it among sixteen recommendations, all approved by the first author.

## Response Summary

- app.py: `_read_files_cached` uses `st.cache_data(..., scope="session")`.
- requirements.txt and pyproject.toml: `streamlit>=1.66.0` (was `>=1.30.0`), the version tested here; older releases may lack the `scope` argument, and a server installing one would fail at start.
- CHANGELOG: the P050 entry says the cache is kept per session.

## Decision

No methodological change. The privacy statements in the app and on the website stay as they are and are accurate again.
